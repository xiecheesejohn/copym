# copym

用 Rust 编写的现代化、高性能、跨平台（Linux / Windows / macOS，另有安卓端）剪贴板管理器。

- **低占用、秒开**：守护进程约 9 MB 内存、空闲 0% CPU；弹窗进程默认在后台预加载（约 35 MB），按快捷键后约 10 ms 就画出界面。不在乎速度时可设 `keep_popup_loaded = false`，改为按需启动、关闭即退出。
- **选中即粘贴**：打开弹窗后直接用方向键 / `j` `k` 选择，按 `Enter` 自动粘贴到之前的窗口（`Shift+Enter` 只复制），可在配置里关闭。
- **原生监听**：Wayland `ext-data-control` / `wlr-data-control`，X11 XFixes，Windows `AddClipboardFormatListener`，macOS `NSPasteboard.changeCount`。
- **跳过密码管理器**：识别 Bitwarden、KeePassXC、1Password 等设置的隐私标记，内容根本不会被读取：
  - Linux：`x-kde-passwordManagerHint = secret`
  - Windows：`ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory = 0`、`Clipboard Viewer Ignore`
  - macOS：`org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType` 等
  - 另外支持按来源应用（Windows/macOS）和正则规则忽略
- **现代界面**：参考 Raycast 的风格——大号无边框搜索栏、按“已固定 / 今天 / 昨天 / 本周 / 更早”分节的紧凑列表、右侧预览加信息表、底部操作栏和 `⌘K` 操作面板；深/浅色跟随系统，全键盘操作。
- **按类型预览**：自动识别链接、颜色、JSON、代码、路径、邮箱、图片——链接显示域名卡片并可在浏览器打开，颜色显示色块与 HEX/RGB/HSL，JSON 自动格式化，代码等宽显示，路径可在文件管理器中打开，图片显示原图（透明背景显示棋盘格）。
- **自定义分组**：用正则（内容或来源应用）、类型、是否固定来定义分组；`Ctrl+1…9`（macOS `⌘1…9`）切换，可指定打开时的默认分组。
- **正则搜索**：点搜索框旁的 `.*` 或按 `Ctrl+R` 切换，大小写不敏感；正则错误会即时提示。
- **搜索图片中的文字（OCR）**：截图等图片在后台低优先级识别文字，之后可以像文本一样搜索（普通/正则均可），预览里显示“图中文字”。
- **局域网加密同步**：多台设备自动发现、端到端加密，同步过来的内容只进入历史，不会改动当前剪贴板。
- **存储**：SQLite（WAL），按千万条设计：启动不加载历史，列表分页，搜索走 trigram 全文索引，分组计数用增量维护的位图；自动去重，超过上限自动淘汰（固定项除外）。详见下文“存储与性能”。

## 安装

下载地址：[Releases](https://github.com/xiecheesejohn/copym/releases/latest)（正式版本）；每次提交的最新构建在 GitHub Actions 的构建产物里（需登录 GitHub），版本号后面带提交号，例如 `copym-0.1.0-4011f23-linux-x86_64.tar.gz`。

- **macOS（Apple 芯片）**：下载 `copym-<版本>-macos-aarch64.dmg`，打开后把 copym 拖进“应用程序”。首次打开时系统会提示“无法验证开发者”（没有 Apple 开发者证书签名），到“系统设置 → 隐私与安全性”底部点“仍要打开”即可。之后按 `Option+C` 呼出，也可以在 Spotlight（`⌘空格`）里搜 copym 打开；在设置（`⌘,`）里打开“登录时自动启动”。
- **Windows**：下载 `copym-<版本>-windows-x86_64.zip`，把里面的 `copym.exe` 解压到固定的目录（例如 `%LOCALAPPDATA%\Programs\copym\`，升级时覆盖同一个文件）运行一次。之后在开始菜单 / Windows 搜索里搜 copym 就能打开（首次运行时自动创建开始菜单快捷方式），然后 `copym autostart on` 开机自启。
- **Linux**：下载 `copym-<版本>-linux-x86_64.tar.gz`，把里面的 `copym` 放到 `~/.local/bin` 等目录运行一次，然后 `copym autostart on`。
- **安卓**：按手机架构下载 `copym-<版本>-android-*.apk`（一般选 `arm64-v8a`）。

## 构建

```sh
cargo build --release          # 产物：target/release/copym
packaging/macos/make-dmg.sh target/release/copym 0.1.0 copym.dmg   # 仅 macOS：打包 .app + DMG
```

发布新版本：把 `Cargo.toml` 的 `version` 改成新版本号并提交，然后打同名 tag 推送，CI 构建完会自动创建 GitHub Release 并上传所有平台的安装包（tag 和版本号不一致时会失败）：

```sh
git tag v0.2.0 && git push origin v0.2.0
```

## 使用

```sh
copym daemon            # 前台运行守护进程（调试用）
copym                   # = copym show：打开/关闭弹窗，必要时自动启动守护进程
copym autostart on      # 登录时自动启动
copym search 发票 | copym search -r '\d{6}'   # 搜索（含图片中的文字）
copym list 20 | copym select ID | copym pause | copym resume | copym clear | copym status
copym quit              # 退出（也可以点弹窗右下角的 ⏻，或按 Ctrl+Q / ⌘Q）
copym config            # 显示配置文件路径
copym groups            # 打开分组管理器
copym sync              # 同步状态；sync pair / sync join 码 / sync leave
copym delete ID         # 删除（已配对设备上同步删除）
copym pin ID            # 固定 / 取消固定
```

### 快捷键

- Windows / macOS / X11：守护进程自动注册全局快捷键，默认 `Alt+C`（macOS 为 `Option+C`），可在配置中修改。
- KDE Plasma（Wayland 与 X11）：通过 KGlobalAccel 原生注册同一个快捷键，无需手动设置。
- 其他 Wayland 桌面（GNOME / Hyprland …）：请在系统设置里把命令 `copym show` 绑定到快捷键。


弹窗完全按 Vim 的方式操作，鼠标可选。打开时处于 NORMAL 模式（`popup_focus = "search"` 则直接进入 INSERT），底栏左侧显示当前模式，按 `?` 随时查看全部按键。

**NORMAL（列表）**

| 按键 | 作用 |
|---|---|
| `j` `k` / `↓` `↑` / `Ctrl-n` `Ctrl-p` / `Ctrl-e` `Ctrl-y` | 下一条 / 上一条，可加计数：`5j` |
| `gg` / `G` / `12G` / `0` `$` | 第一条 / 最后一条 / 第 12 条 |
| `Ctrl-d` `Ctrl-u` / `Ctrl-f` `Ctrl-b` | 半页 / 整页 |
| `H` `M` `L` | 跳到可见区顶部 / 中间 / 底部 |
| `{` `}` | 上一节 / 下一节（已固定、今天、昨天 …） |
| `Enter` / `p` | 粘贴到之前的窗口（`paste_on_enter = false` 时只复制） |
| `yy` / `Y` / `Shift+Enter` | 只复制到剪贴板 |
| `dd` / `x` | 删除 |
| `m{x}` / `mm` | 放进按键为 x 的固定分组（再按一次取消）/ 放进默认的“固定”分组 |
| `'{x}` | 跳到按键为 x 的分组（像 Vim 的标记） |
| `o` | 打开链接（浏览器）或路径（文件管理器） |
| `/` / `i` | 搜索（`/` 清空后重新输入，`i` 保留关键词） |
| `gt` `gT` / `Tab` `Shift+Tab` / `3gt` | 下一个 / 上一个 / 第 3 个分组 |
| `Space` | 操作菜单：每项有一个字母，按下直接执行（`p` 粘贴、`y` 复制、`m` 固定（有多个固定分组时，每个分组一行）、`d` 删除、`b` 不再记录该应用、`r` 暂停记录、`t` 切换外观、`s` 同步、`g` 分组、`,` 设置、`u` 检查更新、`Q` 退出） |
| `:` | 命令行（见下表） |
| `?` | 按键帮助 |
| `Esc` | 依次：取消计数 → 清空搜索 → 关闭 |
| `q` / `ZZ` / `ZQ` | 关闭弹窗 |

**INSERT（搜索框）**：直接输入；`Esc`（或 `Ctrl-[`）回到 NORMAL 并保留关键词；`Ctrl-j` `Ctrl-k` / `↓` `↑` 选择；`Ctrl-u` 清空，`Ctrl-w` 删除一个词；`Enter` 粘贴。

**COMMAND（`:`）**

| 命令 | 作用 |
|---|---|
| `:q` / `:q!` `:qa` | 关闭弹窗 / 退出 copym |
| `:restart` | 重启 copym（改了设置或全局快捷键后；右下角的电源按钮里也有：关闭弹窗 / 重启 / 退出） |
| `:12` | 跳到第 12 条 |
| `:set bg=dark` `light` `system`（或 `:colo dark`） | 外观 |
| `:set lang=zh` `en` `auto` | 界面语言 |
| `:set regex` / `:set noregex` | 正则搜索 |
| `:g 2` / `:g 链接` / `:bn` `:bp` | 切换分组 |
| `:settings` `:sync` `:groups` `:pause` `:resume` `:update` `:help` | 打开对应界面 / 执行（`?` 或 `:help` 列出全部按键和命令，`j` `k` 滚动） |
| `:y` `:p` `:d` `:pin` / `:noh` | 复制、粘贴、删除、固定当前条目 / 清空搜索 |

对话框里同样是 Vim 键：设置（`Ctrl+,`、`:settings` 或菜单里的 `,`）用 `j` `k` 选行、`h` `l` 改值、`Space` 切换开关、`i` 编辑文本、`Tab` / `gt` 切换分类、`Ctrl-S` 保存、`ZZ` 保存并关闭、`q` / `Esc` 关闭；管理分组用 `j` `k` 切换分组、`Ctrl-S` 保存。文本框里按 `Esc` 只退出编辑。

始终可用：`Alt+1…9` 直接粘贴第 N 条，`Ctrl+1…9` 切换分组，`Alt+R` 切换正则，`Alt+K` 打开菜单，`Ctrl+Q` 退出（macOS 上分别是 `⌥`、`⌘`；`⌘S` 固定、`⌘D` 删除、`⌘F` 搜索也保留）。

### 外观和语言

界面是终端风格：等宽字体、黑底磷光绿（深色）或米白纸质终端（浅色），默认跟随系统切换深浅色（Linux 通过 XDG 桌面门户读取并实时跟随）。在菜单里按 `t`、用 `:set bg=dark` 或在设置里手动切换。

界面语言支持中文和英文，默认跟随系统语言（`language = "auto"`），可用 `:set lang=en` 或在设置里切换，命令行输出、错误提示也随之切换。

### 自动粘贴

按 `Enter` 后弹窗先关闭，焦点回到之前的窗口，再模拟一次粘贴快捷键（默认 `Ctrl+V`，macOS `⌘V`，可用 `paste_shortcut` 改成 `shift+insert`、`ctrl+shift+v` 等，例如终端里常用后者）。

- **Windows**：`SendInput`，无需额外设置。
- **macOS**：第一次使用时需要在“系统设置 → 隐私与安全性 → 辅助功能”里允许 copym。安装包用项目自己的证书签名（自签名，"copym Code Signing"），从 0.2.2 起升级后不用重新授权；从 0.2.1 及更早版本升级时，先在列表里用“−”删掉旧的 copym，再重新允许一次。
  - 从终端运行 `copym` 命令也没问题：守护进程会通过 `open` 以 copym.app 的身份启动，权限算在 copym 上，而不是终端上。
- **Linux X11**：XTEST，无需额外设置。
- **Linux Wayland**：通过 `/dev/uinput` 虚拟键盘（当前用户需要有写权限，许多发行版的游戏手柄 / 远程桌面软件包会配好；或者自行添加 udev 规则），否则尝试 `wtype`、`ydotool`。都不可用时内容仍在剪贴板里，下次打开弹窗会提示原因。

## 分组

分组在搜索栏右侧的下拉菜单里（和 Raycast 的类型筛选一样），菜单中显示每个分组的条目数（随搜索实时变化）和快捷键。一个条目可以同时属于多个分组。默认分组：全部、文本、图片、链接、固定。

- **管理**：分组下拉菜单 →“管理分组…”（或操作面板、或运行 `copym groups`），可新建、删除、排序、修改规则，并实时显示当前有多少条匹配。
- **默认分组**：在分组下拉菜单里右键某个分组即设为默认，或在管理器里勾选“打开弹窗时默认显示这个分组”。
- **规则**保存在配置目录的 `groups.toml`，也可以直接编辑：

```toml
default = "全部"          # 打开弹窗时默认显示的分组

[[group]]
name = "验证码"
patterns = ['(验证码|校验码|code)\D{0,12}\d{4,8}']   # 内容（或图片中识别出的文字）匹配任意一条

[[group]]
name = "开发"
apps = ['(?i)code|idea|terminal']                     # 来源应用（Windows / macOS）

[[group]]
name = "其他"
kind = "text"            # text / image / 不写 = 都要
rest = true              # 不属于任何带 patterns / apps 的分组
```

其他字段：`pinned = true` 只包含固定的条目。正则开头加 `(?i)` 忽略大小写。

### 固定分组

固定分组里的条目不按规则匹配，而是手动放进去的。可以建多个，例如“常用回复”“服务器”。每个条目同一时间只在一个固定分组里；固定的条目不会因为超出保存上限被淘汰。

```toml
[[group]]
name = "固定"            # 默认就有：按键 m，所以 mm 就是固定 / 取消固定
pinned = true
board = 1
key = "m"

[[group]]
name = "常用回复"
board = 2               # 固定分组编号，不能重复（管理器里勾选“固定分组”会自动分配）
key = "r"               # 弹窗里 mr 放进来，'r 跳过来
hotkey = "Ctrl+Alt+R"   # 全局快捷键：不打开弹窗，直接把当前剪贴板的内容放进来
```

- **弹窗里**：选中条目后按 `m` + 分组的按键，就放进那个分组；在同一个分组上再按一次就取消固定。按 `m` 后底栏会列出所有可选的分组。也可以用 `Space` 菜单，或输入 `:pin r`、`:unpin`。
- **全局快捷键**：在任何程序里复制后按分组的 `hotkey`，刚复制的内容（也就是历史里最新的一条）就会放进该分组。在管理器里改快捷键后，重启 copym（`:restart` 或 `copym restart`）才生效。
- **命令行**：`copym pin-current [分组]`，分组可以写按键、名称或编号，不写就用第一个固定分组。在没有全局快捷键的 Linux 桌面（GNOME 等）上，可以把这条命令绑定到系统快捷键。KDE 上会自动注册为系统全局快捷键。
- **`board` / `key` / `hotkey` 字段**：在安卓端编辑分组时会原样保留，但安卓端目前只显示固定分组，没有设置这些字段的界面。

## 配置

`~/.config/copym/config.toml`（Windows：`%APPDATA%\copym\config.toml`，macOS：`~/Library/Application Support/copym/config.toml`），首次运行时生成。

| 键 | 默认 | 说明 |
|---|---|---|
| `max_items` | 100000 | 非固定项的最大数量 |
| `max_text_bytes` / `max_image_bytes` | 4 MB / 32 MB | 超过则不记录 |
| `store_images` | true | 是否记录图片 |
| `hotkey` | `Alt+C` | 全局快捷键（macOS 上 Alt = Option） |
| `respect_password_hints` | true | 跳过带隐私标记的内容 |
| `ignore_apps` | bitwarden, keepass, 1password … | 按来源应用忽略（Windows/macOS，名称包含匹配、不区分大小写）；也可以在弹窗操作面板（`⌘K` / `Alt+K`）的“不记录的应用…”里编辑，或对选中条目选“不再记录「某应用」的复制”，立即生效 |
| `ignore_patterns` | [] | 正则，匹配的文本不记录 |
| `restore_empty_clipboard` | true | Wayland：剪贴板被清空时恢复最新一条 |
| `close_on_focus_lost` | true | 弹窗失焦自动关闭 |
| `keep_popup_loaded` | true | 弹窗进程常驻后台，打开更快（约多占 35 MB 内存） |
| `popup_focus` | list | 打开弹窗时键盘在 `list`（列表）还是 `search`（搜索框） |
| `paste_on_enter` | true | `Enter` 自动粘贴到之前的窗口；false 时只复制 |
| `paste_shortcut` | （空 = `ctrl+v` / macOS `cmd+v`） | 粘贴时模拟的按键 |
| `theme` | system | system（跟随系统）/ dark / light |
| `language` | auto | auto（跟随系统）/ zh / en |
| `font` | （空 = 内置等宽字体） | 界面字体文件路径（.ttf / .otf / .ttc，可用 `~/`），例如喜欢的等宽字体；中文仍用系统字体（macOS 苹方、Windows 微软雅黑 UI、Linux fontconfig） |
| `check_updates` | true | 每天检查一次 GitHub Releases 上的新版本（只提示，不自动安装；也可 `copym update` 或操作面板“检查更新”） |
| `ocr_enabled` | true | 识别图片中的文字 |
| `ocr_engine` | auto | auto / native / ppocr（Linux 内置）/ tesseract / off |
| `ocr_languages` | chi_sim+chi_tra+eng | Tesseract 语言（未安装的自动跳过；内置引擎不需要） |

## 图片文字识别（OCR）

| 平台 | 引擎 | 需要安装 |
|---|---|---|
| macOS | Apple Vision（系统自带） | 无 |
| Windows | Windows.Media.Ocr（系统自带） | 对应语言的 OCR 语言包（中文系统一般已带） |
| Linux | PP-OCRv6 tiny（内置，模型已打包进程序） | 无 |
| 任意平台（`ocr_engine = "tesseract"`） | Tesseract | `sudo dnf install tesseract tesseract-langpack-chi_sim`（Debian/Ubuntu：`tesseract-ocr tesseract-ocr-chi-sim`） |

识别在单独的后台线程中进行（Linux 上 nice 19、单核），不影响复制；更换引擎后重启守护进程，旧图片会自动补识别。

**Linux 内置引擎**：[PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) 的 PP-OCRv6 tiny 模型（检测 + 识别共 6.3 MB，Apache-2.0，见 [models/ppocr](models/ppocr/README.md)），用纯 Rust 的 [tract](https://github.com/sonos/tract) 运行，不依赖系统库。简体、繁体、英文混排都能识别；模型在第一次识别时加载，空闲 60 秒后释放。代价是 Linux 版程序从约 11 MB 增加到约 36 MB。

**中文识别质量**：识别前会自动做预处理——透明背景铺白底、深色主题反相、按估计的文字行高把小字放大到引擎最擅长的尺寸（Tesseract），长截图切块识别并去掉重叠（内置引擎 / Vision / Windows）。Vision 只用配置的语言（默认简中、繁中、英文，不再混入日文和韩文），并能识别长截图里的小字；Windows 装了中文 OCR 语言包时优先用中文引擎。

Linux 上实测（字符错误率，越低越好；单核、不含模型加载）。测试图：1 倍屏中文界面截图 9 张（13/15px、12px 灰字、深色模式、透明背景、2 倍屏、繁体、技术文本、宋体）+ copym 弹窗真实截图 1 张：

| 引擎 | 1 倍屏界面 | 繁体 | 真实截图 | 平均 | 每张耗时 |
|---|---|---|---|---|---|
| **PP-OCRv6 tiny（内置）** | 0% | 11% | 4% | **1.5%** | 约 0.1 s |
| Tesseract + 高精度模型（预处理后） | 6–17% | 6% | 35% | 13.6% | 约 0.7 s |
| OCRia-nano-1（对比用，未采用） | 1–8% | 5% | 9% | 4.5% | 约 0.1 s |

2880×1800 的高分屏截图和 1080×6000 的手机长截图也能完整识别（错误率 0.1% / 2.6%）。

```sh
copym ocr 截图.png      # 直接识别一张图片，显示使用的引擎和耗时
copym ocr models        # 下载 Tesseract 高精度模型（tessdata_best，约 30 MB），Tesseract 引擎自动使用
copym ocr redo          # 用当前引擎重新识别所有已保存的图片
```

升级到新的识别流程后，守护进程会自动在后台把已有图片重新识别一遍。

## 局域网同步

1. 在已有的设备上：弹窗右上角 **同步 → 添加设备**，或运行 `copym sync pair`，得到 8 位配对码（3 分钟内有效，只能尝试一次）。
2. 在新设备上：**同步 → 加入另一台设备** 输入配对码，或运行 `copym sync join 1234-5678`。
   局域网屏蔽了 mDNS 时，使用配对码后附带的地址：`copym sync join 1234-5678@192.168.1.20:41234`。
3. 之后同一局域网内的已配对设备会自动互相连接：新复制的内容实时推送；重新连上时补齐离线期间的条目和删除操作。

| 机制 | 说明 |
|---|---|
| 发现 | mDNS（`_copym._tcp`），只广播随机设备 ID 和不可逆的组标识；也可在 `sync_peers` 写死 `IP:端口` |
| 传输 | TCP + Noise `NNpsk0`（X25519 + ChaCha20-Poly1305 + BLAKE2s）。256 位组密钥作 PSK，每条连接都有新的临时密钥（前向保密）；不在组内的设备连握手都无法完成 |
| 配对 | 8 位一次性配对码 + SPAKE2（口令认证密钥交换），配对码本身不在网络上传输；猜错一次即作废，无法暴力破解 |
| 同步规则 | 按内容哈希去重；收到的条目保留原始复制时间、标注来源设备、只进历史；删除会同步（固定项除外）；本机的忽略规则同样作用于收到的内容；密码类内容本来就不会记录，因此也不会被同步 |
| 防火墙 | 需要放行 TCP 47800（`sync_port`）和 UDP 5353（mDNS）。Fedora Workstation 默认已放行；Windows 首次运行会弹出防火墙提示 |

同步核心是独立的纯 Rust 库 `crates/copym-sync`（不依赖桌面代码和任何 C 库），桌面端和安卓端共用同一份代码，协议完全兼容。

| 配置 | 默认 | 说明 |
|---|---|---|
| `sync_enabled` | true | 未配对时不会连接任何设备 |
| `device_name` | 主机名 | 在其他设备上显示的名称 |
| `sync_port` | 47800 | 被占用时自动换成随机端口 |
| `sync_images` / `sync_max_image_bytes` | true / 8 MB | 是否同步图片及大小上限 |
| `sync_history_items` | 200 | 重新连接时互相对比的最近条目数 |
| `sync_peers` | [] | mDNS 不可用时手动指定的 `IP:端口` |

## 安卓端

`android/` 是原生安卓 App（Kotlin + Jetpack Compose，Material 3 动态取色，Android 8.0+）。历史存储和同步直接复用桌面端的 Rust 代码（`crates/copym-core` + `crates/copym-sync`，通过 JNI 调用），按架构分包：arm64 约 3.4 MB，通用包约 8 MB。

**系统限制**：Android 10 起系统禁止后台应用读取剪贴板，所以手机端不能像电脑那样自动记录每一次复制。copym 的做法：

| 方向 | 方式 |
|---|---|
| 电脑 → 手机 | 配对后，电脑上的复制自动同步进手机的历史；点一下条目即复制到手机剪贴板 |
| 手机 → 历史 / 电脑 | ① 复制后打开 copym，自动保存当前剪贴板 ② 任意 App 中“分享 → 保存到 copym”（文字、图片）③ 通知栏快捷开关“保存剪贴板” |
| 隐私 | 带有系统敏感标记（`EXTRA_IS_SENSITIVE`，密码管理器会设置）的内容不保存；同步组密钥不参与系统备份 |

其他功能：
- **分组**：和电脑版相同的规则（同一种 `groups.toml` 格式），顶部标签显示数量；长按标签可设为默认或编辑；菜单 →“管理分组…”可新建、排序、删除，实时显示匹配条数。来源正则可以匹配同步过来的设备名，例如建一个“来自电脑”的分组。
- **按类型显示与预览**：列表里链接显示域名、颜色显示色块、代码和 JSON 用等宽字体；长按条目打开预览——颜色给出 HEX / RGB / HSL（可单独复制）、JSON 自动格式化、链接可在浏览器打开、邮箱可直接写邮件、图片显示原图和识别出的文字。
- **外接键盘**：`↑↓`、Vim（搜索框外 `j` / `k`，任意位置 `Ctrl+J` / `Ctrl+K`）、Emacs（`Ctrl+N` / `Ctrl+P`）上下选择；`Enter` 复制；`Tab` / `Ctrl+1…9` 切换分组；`Alt+1…9` 复制第 N 条；`Ctrl+S` 固定；`Ctrl+D` 删除；`/` 聚焦搜索框；`Esc` 清空搜索。
- 搜索 / 正则搜索、清空历史、配对码配对（生成或加入）、手动地址（Wi-Fi 屏蔽 mDNS 时用），以及可选的“后台保持同步”（前台服务；Android 15 起系统限制每天 6 小时）。右上角菜单和后台通知里都有“退出”，会停止同步并结束进程。

构建（需要 Android SDK 35、NDK r27c、JDK 17+、Rust 安卓目标和 `cargo-ndk`）：

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
cargo install cargo-ndk
cd android && ./gradlew assembleRelease   # Gradle 会先调用 cargo-ndk 编译 Rust 库
# 产物：android/app/build/outputs/apk/release/app-{arm64-v8a,armeabi-v7a,x86_64,universal}-release.apk
```

未设置 `COPYM_KEYSTORE` 等签名环境变量时，release 包使用本机 debug 密钥签名，适合自用；不同机器打出的包签名不同，不能互相覆盖安装。

## 存储与性能

历史存在数据目录的 `history.sqlite`（SQLite，WAL 模式），按 1000 万条设计。要保留这么多条，把 `max_items` 调大（默认 10 万）。

- **启动不加载历史**：只读两个计数器；列表按“时间 + id”分页，界面滚到哪里取到哪里。
- **id 即时间**：`id = 复制时间 << 20 | 序号`，倒序遍历主键就是最新优先；其他设备同步来的条目按原时间插到对应位置。
- **冷热分离**（借鉴 ClickHouse）：`items` 表只放元数据；正文单独一张表，超过 256 字节用 LZ4 压缩，只在预览、搜索命中和规则判断时读取。预览不另存，从正文截取。
- **搜索**：FTS5 trigram 索引，任意子串、中英文都能用。
  - 索引用 `detail=none` 且不存原文，大小约为正文的 0.9 倍（常规全文索引是 2–3 倍）。
  - 每个候选都会回到原文再核对一遍，索引只负责缩小范围。
  - 多个词时，先用全部 trigram 精确查询 30 ms；查不完就改用“最少见的那个 trigram + 原文核对”，按时间窗口往前推进。原因是 FTS5 的 AND 查询在完全没有结果时会走完整个索引，单个词才能按范围停下。
  - 1–2 个字的词和正则无法用索引，就从新到旧扫描。
  - 每次请求最多 80 ms，到时间先返回已找到的，界面继续取下一页（底栏显示“搜索中…”）。
- **分组计数**（类似物化视图）：
  - 按内容或来源应用正则定义的分组，成员关系存在 `members` 表，和每次写入在同一个事务里更新，崩溃也不会不一致。新规则在后台分小步建立。
  - 只按类型或固定状态定义的分组直接用索引和计数器。
  - 搜索时的计数只统计前 1000 个结果，显示为 “1000+”。
- **没采用的方案**：DuckDB 和 ClickHouse 都是列存分析引擎，擅长批量扫描和聚合，但不适合这里的场景（逐条写入、按 id 读写、子串搜索中文）；而且体积大（ClickHouse 还需要单独的服务）。上面采用的是它们的思路：冷热分离、压缩、跳过无关数据、物化视图、限时并逐步返回结果。

压测：`cargo run --release -p copym-core --example bench -- 10000000 <路径>`。以下是本机的数据：Linux，NVMe，数据已在系统缓存中；生成的数据平均每条约 410 字节，同步来的条目不计入。

| 1000 万条 | 结果 |
|---|---|
| 数据库大小 | 7.9 GB（原文约 4.1 GB） |
| 启动 | 0.3 ms，内存 5 MB |
| 第一页 / 下一页（200 条） | 0.6 ms / 0.4 ms |
| 搜索：常见词 / 少见词 / 中文 / 单字 | p95 1.8 / 1.6 / 1.3 / 1.5 ms |
| 正则 | 到 80 ms 先返回部分结果，然后继续扫描 |
| 新增一条 | p50 0.2 ms，p95 2.2 ms |
| 分组计数 / 稀疏分组翻页 | 0.0 ms / 0.5 ms |
| 新分组规则后台建立 | 约 14 秒（建立过程中计数显示 “n+”） |
| 常驻内存 | 25 MB |

**最慢的情况**：搜索结果为空时，要查完全部历史才能确定没有。
- 两个常见词从不同时出现：约 13 秒。
- 正则查不到：约 76 秒（要解压并核对全部正文）。

这期间界面不卡：每 80 ms 刷新一次，结果边找边显示。

## 架构

```
src/
  main.rs          CLI 入口
  daemon.rs        守护进程：监听 → 过滤 → 存储；IPC 服务；全局快捷键；弹窗进程管理
  clip/            各平台剪贴板后端（wayland/ x11 windows macos + arboard 读写）
  ipc.rs           本地 socket（Unix 0700 目录 / Windows 命名管道）+ postcard 帧
  gui.rs           egui 弹窗（列表、按类型预览、分组栏、分组管理器、同步面板）
  paste.rs         自动粘贴：模拟粘贴快捷键（SendInput / CGEvent / XTEST / uinput）
  groups.rs        分组定义（groups.toml）
  filter.rs        应用 / 正则 / 大小过滤
  ocr.rs           图片文字识别（Vision / Windows.Media.Ocr / 内置 PP-OCR / Tesseract）
  ppocr.rs         Linux 内置 OCR：PP-OCRv6 tiny on tract（模型在 models/ppocr/）
  update.rs        检查新版本（GitHub Releases，系统 curl）
  gui/settings.rs  设置界面（每项一个图标，Vim 键操作）
  gui/vim.rs       Vim 键位：NORMAL / INSERT / COMMAND、:命令、按键帮助
  gui/shots.rs     离屏渲染界面截图的测试（COPYM_SHOTS=目录）
  icons.rs         图标（Lucide 子集，assets/fonts/copym-icons.ttf）
  system_theme.rs  Linux：通过 XDG 桌面门户跟随系统深浅色
  kde_hotkey.rs    KDE 全局快捷键（KGlobalAccel D-Bus）
crates/copym-core/ 桌面与安卓共用：历史存储（SQLite + FTS5 trigram + roaring 位图）、数据模型、PNG 工具
  examples/bench.rs 存储压测（生成 N 条假数据，测启动 / 翻页 / 搜索 / 写入 / 计数 / 内存）
crates/copym-sync/ 局域网加密同步核心（平台无关）
  channel.rs       Noise 加密通道与分帧
  identity.rs      设备 ID / 组密钥持久化
  protocol.rs      同步消息
  lib.rs           发现、连接管理、配对、同步引擎
crates/copym-android/ 安卓 JNI 库（app.rs 业务逻辑 + lib.rs JNI 导出）
android/           安卓 App（Kotlin + Compose）
packaging/macos/   .app 的 Info.plist 与 DMG 打包脚本
assets/            应用图标（svg / png / Windows 用的 ico）、键位符号字体（fonts/）
build.rs           Windows：把图标和版本信息嵌入 copym.exe
```
